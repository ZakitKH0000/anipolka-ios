# Исправление автоматических обложек — исходники, без сборки

Подготовлено 23 октября 2026. Эти изменения пока **не входят в опубликованный IPA 1.1.0**. Номер версии не менялся; новый IPA, Xcode-сборка, GitHub Actions и публикация не запускались. Сборка ожидает явного согласия владельца.

## Причина

Старый REST API Shikimori для части произведений возвращает `/assets/globals/missing_original.jpg`. Это JPEG с текстом «404 not found», который сервер отдаёт с HTTP 200. Проверка успешного ответа и декодирования картинки принимала его за обложку. Непустой результат поиска Shikimori также останавливал переход к Kitsu, даже когда настоящего изображения не было.

## Изменения

- Для актуальных постеров используется публичный GraphQL Shikimori: `poster.originalUrl` и `poster.mainUrl`. REST остаётся резервным источником названий и идентификаторов.
- Известные URL заглушек исключены из поиска, предпросмотра и кэширования. Загрузка проверяет статус HTTP, тип `image/*`, конечный URL после перенаправления и декодирование изображения.
- Если изображение пустое, отсутствует, повреждено или не загружается, подбор продолжается в Kitsu по оригинальному названию. Проверяются точное название/алиасы, известный год и формат; неоднозначное совпадение не выбирается автоматически.
- Только успешно загруженный постер сохраняется вместе с метаданными. Если картинка пришла из Kitsu для произведения Shikimori, исходный Shikimori ID сохраняется; Kitsu ID никогда не записывается вместо него.
- Если у записи сохранён Shikimori ID, но его название подтвердить не удалось (нет оригинального названия и Shikimori временно недоступен), резервный поиск по пользовательскому названию не выполняется: подбор повторится позже, выбранное произведение не заменяется.
- При загрузке коллекции и восстановлении резервной копии удаляются только старые узнаваемые заглушки. Идентификатор произведения остаётся для повторного поиска; свои фото, названия, прогресс, порядок и настройки не меняются.
- Завершившийся запрос не перезаписывает обложку после ручной замены, удаления записи, переименования или отключения подбора. Продвижение просмотренного номера во время загрузки сохраняется.
- Пауза после HTTP 429 применяется отдельно к каждому каталогу, поэтому ограничение Shikimori не блокирует Kitsu.

## Выполненные проверки

- `python -X utf8 scripts/check_catalog.py` — успешно: GraphQL вернул настоящие изображения двух конкретных произведений, включая случай старой заглушки; Kitsu вернул отдельные сезоны и изображение китайского сериала с совпадающими оригинальным названием, годом и форматом.
- Разбор синтаксиса Tree-sitter: 19 Swift-файлов, ошибок разбора нет. Это не проверка компилятором Swift.

## Подготовленные проверки, ещё не выполненные

`Core/Tests/ShelfCoreTests/CoverLookupTests.swift` (11 методов): HTTP-200 заглушки, HTML/404 вместо изображения, GraphQL и отсутствующий постер, переход к Kitsu после ошибки/пустого изображения/недоступности каталога, запрет резервного поиска при неподтверждённом сохранённом ID, отказ от другого года/сезона и неоднозначных вариантов, алиасы, сохранение исходного ID, отмена запроса, очистка старого кэша, сохранение прогресса и защита ручных изменений.

Swift/Xcode на текущем Windows-хосте недоступны. XCTest, компиляция для iPhone, тесты UI и проверка исправленного приложения на телефоне **ещё не выполнены**. После разрешения на сборку нужно выполнить их до выдачи нового IPA. Уже установленное приложение на телефоне этой правкой не обновлялось.
